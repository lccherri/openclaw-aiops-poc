# Launch layer: aap-actions

Intent-level MCP tools between the agent and AAP. Rationale and diagram:
[docs/architecture.md](../../../docs/architecture.md#launch-layer-aap-actions).

| File | Content |
|---|---|
| [server.py](server.py) | MCP server (streamable HTTP, JSON, stateless), Python standard library only |
| [deployment.yaml](deployment.yaml) | Deployment (restricted, no ServiceAccount token, read-only root FS), Service, egress NetworkPolicy (DNS + AAP gateway only) |

The code is mounted from the ConfigMap `aap-actions-code`, generated by
[../kustomization.yaml](../kustomization.yaml) (a code change rolls the Deployment).

| Tool | Arguments | AAP call |
|---|---|---|
| `launch_remediation` | `workflow` (`wf-restart-deployment` / `wf-rollback-deployment` / `wf-scale-deployment`), `deployment`, `namespace` (`demo-apps`), `replicas` (`"1"`-`"5"`, scale only) | `POST /workflow_job_templates/{id}/launch/` |
| `remediation_status` | `workflow_job_id` | `GET /workflow_jobs/{id}/`, its nodes, and the approval record |
| `collect_diagnostics` | `app`, `namespace` | `POST /job_templates/{id}/launch/` |

Rules for changing it:

- **Arguments stay strings**, ids and numbers included: the corporate MaaS streaming parser
  drops the end of a call whose last argument is a number or an object (test-log F-18). Check
  new tools with `model-validation/streaming_args_test.py`.
- **No credential in the server.** It forwards the caller's `Authorization` header; AAP RBAC,
  surveys, the playbook guard and approval nodes stay the control.
- Every launch is logged as `AUDIT ...` with the AAP job id (no headers, no tokens).

```bash
make tools                                            # deploy / update
oc -n aiops-tools logs deploy/aap-actions | grep AUDIT
```
