# OpenClaw via the RHOAI agentic starter kit

OpenClaw is deployed with the Red Hat OpenShift AI agentic starter kit
([red-hat-data-services/agentic-starter-kits](https://github.com/red-hat-data-services/agentic-starter-kits),
`agents/openclaw`), used as a **kustomize remote base pinned to commit `3778e00`**
(tested by the kit on OpenShift 4.22 with OpenClaw 2026.9.8).

> The kit uses the upstream community image `ghcr.io/openclaw/openclaw` (pinned by digest),
> which is not built or validated by Red Hat - see the kit's README.

```text
starter-kit/
├── kustomization.yaml          # ../base (namespace, NetworkPolicies, ExternalSecret) + kit
└── kit/
    ├── kustomization.yaml      # remote base (pinned) + POC patches, namespace openclaw
    ├── deployment-patch.yaml   # tracing sidecar, workspace rules, env, no SA token in gateway
    ├── rbac.yaml               # SA openclaw-tracing -> mlflow-operator-mlflow-integration
    └── otel-collector-config.yaml.tmpl   # from the kit's overlays/mlflow-tracing
```

| Kit default | POC overlay |
|---|---|
| `openclaw-secrets` with placeholder token | Deleted; generated by ESO from `poc-vault` |
| Sample `openclaw-config` | Replaced by `openclaw-poc-config` (`../openclaw/openclaw.json5`) |
| PVC `gp3-csi` | `ocs-external-storagecluster-ceph-rbd` |
| No NetworkPolicy | Default-deny + explicit allows (`../base`) |
| Tracing overlay mounts the SA token in the whole pod | Projected token mounted only in the `otel-collector` container |
| — | `AGENTS.md` seeded into the workspace; `NODE_EXTRA_CA_CERTS` for the MaaS gateway |

Deploy with `make agent`. Build offline is not possible: kustomize fetches the remote base
(git + network required).
